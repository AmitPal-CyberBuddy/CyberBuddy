CSP Policy Auditor

Audit the enforced Content-Security-Policy response header for dangerous script sources, unsafe fallbacks, missing navigation controls, and reporting gaps.

Aligned with OWASP WSTG-CONF-12 · CWE-79 · CWE-693

New to this check? Read the 5-minute CSP guide first.

📋 Analyze a pasted CSP header instead of a URL

Paste a raw Content-Security-Policy (or Content-Security-Policy-Report-Only) header value — with or without the header name — to audit it directly. This runs entirely in your browser: no network request is made and no target is contacted.

ℹ What this audit can prove

CyberBuddy reads the CSP sent in the target's HTTP response. It distinguishes an enforced policy from Content-Security-Policy-Report-Only, which records violations but blocks nothing.

Read-only GET→CSP response header→Directive audit

A meta CSP inside the response body is not visible to a header-only hosted lookup, and some directives — especially frame-ancestors — do not work in meta policies. Run python3 server.py for first-party response-header evidence without a public relay.
