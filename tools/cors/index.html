Tool 03 · cross-origin policy

CORS Validator

CORS is the browser's permission system for cross-origin reads. The danger isn't CORS itself — it's lazy CORS: reflecting any origin, allowing credentials from everywhere, or forgetting Vary: Origin so caches poison the policy.

With server.py the engine sends two GETs from distinct probe Origins so reflection can be proven. Without it, the page falls back to a cookie-less in-browser fetch from this origin only — that cannot tell an allowlist from reflection.

How to read this

  • Fetch blocked — no Access-Control-Allow-Origin for this origin. Restrictive and safe.
  • Origin reflected — proven only by the engine (two distinct Origins echoed). A single browser fetch cannot tell reflection from an allowlist.
  • Allow-origin * + credentials — invalid per spec: browsers refuse credentialed requests when the wildcard is echoed. Some sites send it anyway; we flag it.
  • Vary: Origin — without it, shared caches may serve one origin's CORS headers to everyone. Easy to miss, real-world exploited.
