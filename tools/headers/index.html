Tool 02 · response hardening

Security Headers

Pull the response headers of a URL and grade the missing and weak ones: CSP, X-Frame-Options, HSTS, X-Content-Type-Options, Referrer-Policy, Permissions-Policy and the COOP / COEP / CORP family. Every finding shows the raw header value it was based on.

Header reads are done server-side by server.py — browsers can't read cross-origin response headers on their own. Scan only systems you own or are authorized to assess.

Only the headers this tool inspects are shown. Non-standard or duplicated headers can hide issues — check with curl -I for the full picture.

Header checks need the local engine

The scan API isn't reachable, so this page can't fetch the target's headers — browsers block cross-origin header reads by design. Two ways to get full reports:

python3 server.py

then open http://127.0.0.1:8080/tools/headers/, or use the engine directly:

python3 security_headers.py https://example.com
! ! Authorized testing only. You may only scan systems you own or have explicit permission to assess. Headers are fetched with a plain GET — no exploits, no payloads — but a request to a system you don't control is still a request you are accountable for. Results are advisory: headers are necessary, not sufficient, for security.
