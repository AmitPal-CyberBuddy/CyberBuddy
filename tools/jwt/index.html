      Sign & build the test token
      
        
      Signing runs in this browser via Web Crypto. The
          header's alg and the selected algorithm must agree;
          alg:none stays rejected.
      
        

        
      
          
          
          
          
        
      
        
      
          
      
            
          
      
          
      
            
            
      Web Crypto cannot read PKCS#1 ("RSA PRIVATE KEY"),
              SEC1 ("EC PRIVATE KEY") or encrypted PEM — convert to PKCS#8 first, e.g.
              openssl pkcs8 -topk8 -nocrypt -in key.pem.
      
          
      
          
      
            
            
      A JWK without d is a public key and cannot sign.

          Privacy & accuracy
          
      
          JWTs can be credentials. Treat every token like a
        password or a session cookie.
          
      
            
        
          • Fully local: decoding and verification run in this
          browser via Web Crypto. No relays, no target requests, no storage,
          no query/share state carrying a token.
            • 
        
          • Decoding is not verification. Anyone can read the
          header and payload without a key; that proves nothing about who
          issued it.
            • 
        
          • A valid signature with a key you supply proves only a
          match with that key, not that the target trusts it.
            • 
        
          • A generated or re-signed token is a TEST TOKEN and a
          variant is a TEST TEMPLATE — not proof of acceptance.
          Building the bytes proves nothing until the target actually honors
          the token; a secret-testing match is a discovered secret for your
          own testing, never a verdict about the target.
            • 
        
          • VAPT suggestions are prioritized test vectors, never
          findings. They are derived from the decoded token's
          structure, cover the classic JWS attack classes, and every
          one-click payload is labelled TEST PAYLOAD for authorized
          assessment. Only the target's response in Burp Suite decides
          whether a vector matters.
            • 
        
          • Live target testing is not part of the hosted tool.
          CyberBuddy will not send a JWT to a target, a JWKS URL or a third party.
            • 
        
          • Context over score. There is no numeric security
          score; observations such as a missing exp are reported
          in context, never as an automatic verdict.

          What the Workbench does
          
    
          
      
          
        Decode & inspect
        
          Read a token honestly
          
        
          Strict compact-JWS parsing, header and payload display, a claim
          timeline for iat/nbf/exp, and
          observations in context — no persistence, no network.
          
      
          
      
          
        Verify
        
          Check the signature
          
        
          HMAC, RSA-PKCS#1, RSA-PSS and ECDSA verification through Web Crypto
          with the key you supply. The token's own alg never picks
          the verifier, so algorithm confusion cannot slip through.
          
      
          
      
          
        Edit & sign
        
          Rebuild a test token
          
        
          Header and payload editors, standard-claim helpers, a semantic diff,
          local RSA test-key generation, and signing that labels every output a
          TEST TOKEN.
          
      
          
      
          
        Test
        
          VAPT suggestions, templates & secret testing
          
        
          Context-aware VAPT suggestions with one-click TEST PAYLOADs and
          Burp-ready copy, plus alg:none, claim tampering,
          algorithm confusion, embedded JWK, jku/x5u
          and kid templates, and bounded HS256/384/512 secret
          testing in a Web Worker with progress and cancel.
          
      
          
    
          
  
          

  
          
    ! !
    Authorized testing only. Verify and test JWTs and
      systems you own or have written permission to assess. The Workbench
