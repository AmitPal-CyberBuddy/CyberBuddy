JWT Security Workbench

Decode · Audit · Verify — locally in your browser. Paste a JWT and inspect its claims; supply a key to verify its signature. No token ever leaves this browser.

RFC 7519 · RFC 7515 · OWASP WSTG-SESS-10 · CWE-347

Read the concise JWT guide for how decoding differs from verification.

The token is parsed in this tab only. It is never sent, stored, cached or placed in the URL.

    Privacy & accuracy
    
      
    JWTs can be credentials. Treat every token like a
        password or a session cookie.
    
      
      
        
    • Fully local: decoding and verification run in this
          browser via Web Crypto. No relays, no target requests, no storage,
          no query/share state carrying a token.
      • 
        
    • Decoding is not verification. Anyone can read the
          header and payload without a key; that proves nothing about who
          issued it.
      • 
        
    • A valid signature with a key you supply proves only a
          match with that key, not that the target trusts it.
      • 
        
    • Generated variants (JWT-02/03) will not prove server
          acceptance — a re-signed or alg:none
          token is a test case until the target actually honors it.
      • 
        
    • Live target testing is not part of the hosted tool.
          CyberBuddy will not send a JWT to a target, a JWKS URL or a third party.
      • 
        
    • Context over score. There is no numeric security
          score; observations such as a missing exp are reported
          in context, never as an automatic verdict.
      •

        guide for the background behind each statement.
