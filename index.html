What CyberBuddy is — and is not

read-only by design

What CyberBuddy does

  • Non-destructive HTTP checks — a GET baseline plus analyst-selected HEAD, OPTIONS, and preflight simulation for CORS
  • Header inspection — the raw value behind every assessed finding
  • DNS posture analysis — public records through a resolver, never the target's servers
  • CORS analysis — cross-origin access posture with explicit method coverage
  • Framing analysis — live clickjacking proof
  • CSRF PoC generation — standalone HTML from a pasted request, fully local and inert inside CyberBuddy
  • JWT analysis & verification — local decode, claim inspection, crypto verification, prioritized VAPT test suggestions & payloads, variant generation and bounded secret testing
  • Evidence collection — screenshot-ready report cards

What it does not do

  • Automatic exploitation — generated PoCs and JWT test artifacts stay inert until you deliberately export and use them
  • Login attacks — no credential submission, spraying, or authentication bypass automation
  • State-changing HTTP requests — CyberBuddy never sends POST, PUT, PATCH, or DELETE to a target
  • Credential collection — tokens, keys and requests processed locally never leave your browser
  • Silent third-party sharing — relays and hosted DNS lookups require consent and disclose exactly what leaves the page

How CyberBuddy scores

python · cache · live Full methodology reference →

Clickjacking

Restrictive frame-ancestors is low risk. X-Frame-Options alone is medium. frame-ancestors * or neither control is high. The live iframe is the proof — if the real UI appears, the page can be framed in this browser.

Headers (0–100)

CSP 25 · XFO 15 · HSTS 15 · nosniff 10 · Referrer-Policy 10 · Permissions-Policy 5 · COOP/COEP/CORP 5 each. A ≥ 90, B ≥ 75, C ≥ 60, D ≥ 45, else F. Every finding shows the raw value it used.

CORS

The Python engine probes two origins to prove reflection vs an allowlist. When no CORS headers are sent, cross-origin reads are blocked by default (PASS). On GitHub Pages the browser performs a single-origin probe.

CSP

Risk comes from the highest-confidence policy gap — no fake /100. Missing enforcement or dangerous script execution is high; missing hardening directives is medium; a restrictive policy with only optional observations is low.

JWT Workbench

Local cryptographic verification and claim validation via Web Crypto API. Builds test templates (alg:none, key confusion, embedded JWK, kid traversal), derives prioritized VAPT suggestions with one-click TEST PAYLOADs and Burp steps, and tests HMAC secrets offline. Zero network transmission.

Hosted scan layers

Python when server.py or api/ is up. Otherwise a same-origin published report for the demo targets in urls.txt (fresh within 48h). Otherwise a direct read, then opt-in relays. The source chip always says which layer ran.

Privacy

Scan history stays in this browser (localStorage, 24h) — never uploaded, never shared. Published reports cover only the demo targets, never yours. Third-party header relays are opt-in, send the hostname only by default, and their output is flagged unverified. Full detail →
